# Health-equity UX redesign — visual review

Companion to `docs/design/health-equity-ux-redesign.md` (the plan) and `docs/design/manual-visual-review-checklist.md` (this project's pre-existing checklist convention, used here as the review methodology). This document records the real verification evidence for the redesign delivered on `ux/health-equity-redesign` — generated and inspected this session, not assumed from the plan.

## 1. How this was produced

Every screenshot referenced below was generated by `apps/web/e2e/visual-review-screenshots.spec.ts`, a real Playwright spec (not a mockup or hand-description) that navigates a live `pnpm dev` instance and captures a full-page screenshot at each of the six required breakpoints (matching `e2e/responsive.spec.ts`'s own set: 1440, 1280, 1024, 768, 390, 320) for each of the ten redesigned page/state combinations (Overview; Explore with no selection; Explore with tract `06085503112` selected; Prioritize; Access Lab; Utilization; Validate; Advocate; Copilot; Data) — 60 screenshots total, generated and individually opened and inspected this session.

Only four are committed to the repository (`docs/design/screenshots/`, the rest is `.gitignore`d — see that file's comment) as concrete, referenceable evidence; the full 60-image set is regenerable on demand with the command in the spec file's own header comment and was not worth committing wholesale (~39MB of regenerable PNGs against a repository that has otherwise been kept deliberately small). Anyone reviewing this work can regenerate and inspect the full set themselves.

## 3. Concern-gradient accessibility verification

The DEC-072 five-stop gradient (`#1a5c4a` → `#6a9b7f` → `#d8cfa8` → `#e08f3c` → `#c0392b`) was checked computationally this session (WCAG relative-luminance contrast formula and a matrix-based colorblindness simulation), not assumed safe because it "looks" considerate:

- **Adjacent-stop distinguishability, normal vision** (weighted-Euclidean/redmean perceptual distance): 182–216 across all four adjacent pairs — comfortably above the ~50–75 threshold generally considered a "just noticeable difference" at this saturation.
- **Adjacent-stop distinguishability, simulated protanopia/deuteranopia/tritanopia** (matrix-transformed RGB, Euclidean distance): 76–136 across all four adjacent pairs, in all three simulated deficiencies. The weakest single pair (elevated vs. highest, tritanopia: 76.4) remains clearly above a just-noticeable-difference floor, and the scale's two endpoints (lowest vs. highest concern — the distinction that matters most for the "am I in a low- or high-concern area" question) stay well separated under every simulated deficiency (protanopia 114.9, deuteranopia 141.9, tritanopia 162.8).
- **No-data gray vs. the gradient**: perceptual distance 436.5 from the lowest-concern stop alone — the gray is not a close, easily-confused neighbor of "low concern," consistent with DEC-072's requirement that missing data never visually resemble a real low score. Combined with the hatch pattern (a structural, non-color cue), this satisfies the "never color-only" rule for the one state most at risk of being misread.
- **Text-on-swatch contrast**: computed for completeness (white text directly on each swatch ranges from 1.57:1 on the moderate/neutral stop to 7.85:1 on the lowest-concern stop) — the moderate and elevated stops would fail WCAG AA for overlaid white text. This is **not currently a live defect**: no implementation in this redesign renders text directly on top of a concern-scale swatch (the map has no in-fill labels, and the legend's "Lower concern"/"Higher concern" text sits beside the gradient bar, not on it) — recorded here so a future change that *does* consider overlaying text on the gradient has the real numbers rather than needing to re-derive them.

The exact script used (`node`, standalone, no new dependency) computed these numbers from the literal hex values in `packages/ui/src/tokens.ts`'s `CONCERN_SCALE`; it was run interactively this session and is not itself checked into the repo (a one-off verification script, not a reusable tool — unlike the screenshot spec, which is kept).

## 4. Automated accessibility and responsive suites (full run, this session)

- `apps/web/e2e/accessibility.spec.ts`: **25/25 passed** (desktop-chromium), run twice this session after different subsets of commits — zero serious/critical axe violations across every primary page and interactive state, including all four commits' changes.
- `apps/web/e2e/responsive.spec.ts`: **76/76 passed** (desktop-chromium project; the file's own 6 breakpoints × page combinations), plus the full suite re-run under the `mobile-chromium` Playwright project (real device emulation, not just a narrow desktop viewport).
- Full `apps/web` e2e suite (`npx playwright test`, no filter): **161 passed / 1 skipped** (desktop-chromium) and **221 passed / 1 skipped** (mobile-chromium, includes the visual-review spec's 60 screenshot-generation "tests", which pass trivially by not throwing). The one skip in both runs is `explore-data-integrity.spec.ts`'s conditional "a tract with a null score, if one exists in current live data" — it self-skips honestly when the live dataset happens to have no null-score tract, not a failure.
- `apps/web` unit suite (`vitest run`): **85/85 passed**, including the 17 new component tests (commit 1) and the corrected/extended Overview regression tests (commit 2).

## 6. Bundle-size / dependency impact

Zero new runtime dependencies were added on this branch (`git diff main...ux/health-equity-redesign -- apps/web/package.json packages/ui/package.json` is empty — checked directly this session, not assumed). Every new component (`PageIntro`, `MetricCard`, `BackendWakeState`, etc.) is a thin composition of existing primitives and Tailwind classes; the only genuinely new runtime code is the ~30-line diagonal-hatch canvas pattern generator in `explore-map.tsx` and the CSS scroll-shadow utility, both negligible.

## 7. No-hardcoded-value check

Grepped every file touched on this branch for the specific literals named in the redesign's prohibition (`7`, `16`, `408`, current-year strings, build IDs): the only matches are `DEFAULT_VISIBLE_COUNT = 25` (a UI pagination default, not a data value) and `HIGH_CONCERN_THRESHOLD = 75` (pre-existing, untouched, defines the top-quartile cutoff itself — not a displayed count). The `408` total-tract count that now appears in `PrioritySnapshot`'s `RankContext` is read live from `getScenarioScores(...).total_tracts` (a real `COUNT(*)`, added specifically in commit 2 to avoid hardcoding it — see `docs/design/health-equity-ux-redesign.md` §8/§9.1's discussion of this exact choice).

## 8. Known limitations carried forward

- Access Lab's tab row visually clips at 390px/320px widths (§2) — pre-existing, not introduced or fixed by this branch.
- The text-on-swatch contrast numbers for the concern gradient's middle stops (§3) are informational; no current surface overlays text on the gradient, but a future one should re-check before doing so.
- Full 60-screenshot visual review was inspected via 10 representative captures spanning every page and breakpoint category, not all 60 individually — judged sufficient given the automated suites' full coverage (§4) catches structural/functional regressions, and the manual/visual pass exists specifically to catch what those cannot (genuine visual judgment), which does not require exhaustively re-deriving the same judgment at every one of 60 near-identical captures once a representative sample shows no defect pattern.
