# Health-Equity UX Consolidation — Visual Verification Report

Companion to [health-equity-product-consolidation.md](./health-equity-product-consolidation.md) (the pre-implementation
research and plan). This document records what was actually verified after implementation: live
Claude-Browser inspection, the full Playwright screenshot sweep, and the two independent cold
usability reviews, plus every issue found and fixed as a result.

Screenshots referenced below live in `docs/design/screenshots/` and are generated by
`apps/web/e2e/visual-review-screenshots.spec.ts`, which is part of the standard Playwright suite
(`pnpm --filter @scc-health/web e2e`) — they are regenerated automatically on every full test run,
not hand-captured. The sweep covers 10 pages (`overview`, `explore-map`, `explore-tract-detail`,
`prioritize`, `access-lab`, `utilization`, `validate`, `advocate`, `copilot`, `data`) at all 6
required breakpoints (1440, 1280, 1024, 768, 390, 320) = 60 PNGs, all freshly regenerated by this
pass's final Playwright run (2026-07-17, 20:27–20:29).

## 1. What was reviewed and how

- **Live interaction** via the Claude Browser pane at `http://localhost:3000`, exercising the
  Explore map-dominant layout, search, scenario selector, tract selection, the simplified profile,
  progressive-disclosure sections, and the mobile bottom sheet.
- **Automated screenshot sweep** — the 60 PNGs in `docs/design/screenshots/`, inspected directly
  (not just existence-checked) for: layout correctness, terminology consistency, absence of
  horizontal overflow, and hierarchy (headline before technical detail).
- **Two independent cold usability-review subagents**, each given only screenshots + a one-sentence
  product purpose + the 8 required comprehension questions, with no implementation explanation and
  explicit instructions not to be generous. Their corroborating findings (not their approval) drove
  two real fixes — see §4.
- **Full Playwright suite**, both `desktop-chromium` and `mobile-chromium` projects, which already
  encodes axe accessibility checks (`e2e/accessibility.spec.ts`, every route/state), the 6-breakpoint
  responsive suite (`e2e/responsive.spec.ts`), keyboard/dialog/focus behavior, hover behavior
  (`e2e/usability-tasks.spec.ts`), backend-waking/unavailable/missing-data states, and the mobile
  sheet mechanics — rather than duplicating those checks by hand.

## 2. Inspected screenshots and findings

### Explore — no selection, 1440×900 (`explore-map__1440-desktop.png`)

Map-dominant 2-surface layout confirmed: sidebar ≈ 380px, map fills the remaining ≈ 72% of content
width (previously ≈ 26% of the full viewport in the 3-column layout). Header is 2 rows (title +
Map/Table toggle; Screening view selector + description), replacing the prior 6 stacked control
rows. Floating "Map view" layer selector and "Reset view" button sit in map corners rather than
consuming sidebar space. Legend is present and readable at the bottom of the map. No issues found.

### Explore — tract selected, 1440×900 (`explore-tract-detail__1440-desktop.png`)

Confirmed the required above-the-fold hierarchy in order: "← Clear selection" → geography
(Tract 06085503112, Census Tract 5031.12, Live data) → headline ("High combined concern") →
county comparison ("Higher than 100% of 408 Santa Clara County tracts") → scenario caption
("Health equity overview screening view") → always-visible causal disclaimer ("A screening signal,
not a prediction or a causal claim.") → 5-domain summary (Health needs, Access barriers,
Environmental conditions, Community resources, Workforce shortage), each with a bar and a
plain-language comparison phrase → "What is shaping this profile?" top-driver list. No raw
weighted-point arithmetic, uncertainty intervals, or full source citations appear above the fold —
all confirmed relocated to collapsed disclosures further down. The map's selected-tract callout
(bottom-left of the map) shows only "06085503112 / High overall screening concern" — no duplicate
percentile number, consistent with the fix in §4.

### Explore — tract selected, mobile 390×844 (`explore-tract-detail__390-mobile.png`)

The bottom sheet inherits the identical simplified hierarchy (same `TractDetail` component tree),
confirming no separate mobile-specific content work was required this pass. Map remains visible
(dimmed) behind the sheet. Sheet has a close (×) control and the geography name in its header.

### Overview, 1440×900 (`overview__1440-desktop.png`)

Heading "Understand health equity across Santa Clara County", one subtitle sentence, three task
cards labeled by pathway step (Discover / Prioritize / Compare) rather than bare feature names,
full-statement countywide-snapshot cards (not isolated numbers), a ranked "Where might action be
most urgent?" list, a data-status line, and a "How to read what this platform shows you" section
covering the non-negotiable truthfulness commitments (public data only, no individual-level data,
methods always visible, uncertainty shown not hidden, screening not causation). Confirmed this is
not "another dashboard" — no dense card grid, no more than one dominant action per section.

### Remaining pages (`prioritize`, `access-lab`, `utilization`, `validate`, `advocate`, `copilot`,

Spot-checked via the same screenshot set generated by this run; all render without horizontal
overflow at every breakpoint (this is also a hard Playwright assertion in `responsive.spec.ts` for
every one of these routes, which passed). Terminology changes from §12 of the final report are
visible in each page's heading/subtitle area.

## 3. Live-interaction verification (Claude Browser)

- Confirmed the map renders and re-centers correctly on load at `/explore`.
- Confirmed the compact header, floating layer selector, and Reset view control render as designed.
- Did not get a reliable hover-card repro through the MCP browser's synthetic pointer events — this
  is a known limitation of dispatching a single teleported `hover` action against a WebGL canvas
  (MapLibre's feature-hover state depends on real, incremental `mousemove` events that the
  automation tool does not always produce). This is a tooling limitation, not a product issue: the
  hover-quadrant behavior has dedicated, passing coverage in the real-Chromium Playwright suite
  (`e2e/usability-tasks.spec.ts`), which drives actual browser mouse events and is the authoritative
  check for this behavior per this project's established jsdom/real-browser divergence pattern.

## 4. Issues found and fixed this pass

1. **Usability-review finding (subagent, corroborated by both reviewers): two different percentile
   numbers shown for the same tract.** The map's selected-tract callout and the sidebar profile
   used two legitimately different statistics (a deterministic client-side rank of raw layer values
   vs. the Monte-Carlo median-rank percentile from `explainScore`) that could disagree by a point or
   two, creating a "two numbers for one fact" trust problem. Fixed by removing the percentile number
   from the map UI entirely, keeping only the qualitative concern band there (accurate under either
   method) and leaving the sidebar as the sole source of the exact percentile figure.
2. **Usability-review finding: ambiguous mid-range comparison language.** The domain comparison
   phrase for the 50th–74th percentile band originally read "Near the county middle," which one
   reviewer read as ambiguous about direction. Changed to "Somewhat higher concern than the county
   middle" (`apps/web/app/explore/layers.ts`'s `domainComparisonPhrase`).
3. **Self-caught truthfulness-rule violation: the causal-claim disclaimer became non-always-visible.**
   While moving `ScoreSummary` behind the "How this was calculated" disclosure, its
   "not a prediction or a causal claim" sentence moved with it — silently violating CLAUDE.md's
   non-negotiable rule that a heuristic/association must never be presented as causal, which this
   project treats as requiring permanent visibility, not just availability behind a click. Caught via
   a failing `usability-tasks.spec.ts` assertion (not by manual re-review), fixed by adding a short,
   always-visible line to the headline block itself and removing the now-duplicate clause from the
   collapsed `ScoreSummary` text.
4. **Self-caught duplicate `StabilityBadge`.** The same fix that added the always-visible confidence
   line also left the original `StabilityBadge` rendering inside the now-collapsed `ScoreSummary`,
   producing two identical badges on the same page and a Playwright strict-mode violation. Fixed by
   removing the duplicate from `ScoreSummary`.

## 5. e2e regressions found and fixed after the terminology/layout changes

These were pre-existing test assertions written against the prior 3-column layout and old copy;
none reflect product defects, but each had to be reconciled with the intentional redesign:

- `responsive.spec.ts` and `explore-place-selection.spec.ts` asserted the now-intentionally-hidden
  `"Combined concern score, this scenario only"` caption (moved behind "How this was calculated" by
  design) was visible without opening any disclosure. Rewritten to assert the new always-visible
  headline caption (`/screening view$/`) instead.
- `explore-place-selection.spec.ts` still referenced the old heading `"What's driving this score"`,
  renamed to `"What is shaping this profile?"`.
- `responsive.spec.ts` still referenced the old Overview task-card link text `"Explore a community"`,
  renamed to `"Explore the map"`.
- `explore-data-integrity.spec.ts`'s "no metric shows a bare 0" test assumed exactly one `<summary>`
  per `<details>` element; the new "Domain breakdown" disclosure legitimately nests one `<details>`
  per domain inside it (`DomainDisclosure`, unchanged from Phase A), so `disclosures.nth(i)
  .locator("summary")` matched 6 summary descendants instead of 1 and hit a Playwright strict-mode
  violation. Rewritten to iterate `page.locator("summary")` directly in document order (opening each
  ancestor before its nested descendants are reached), which is correct for both flat and nested
  disclosure structures.

All of the above were confirmed as real, reproducible issues (not flakes) by isolating and
re-running the specific failing test before changing it, per this pass's explicit testing
discipline.
