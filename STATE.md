**Phase 4 — built the full analytics/scoring/uncertainty/decision-engine layer on top of the Phase 3 warehouse:**

- **Metric registry** (`metrics/registry.py`, `config/metrics.yml`): 25 real metrics across 5 domains, 4 transform types (`none`, `acs_ratio`, `acs_sum_ratio`, `precomputed`), each with plain-language definition/interpretation/limitations/citation. Validated against the live warehouse at pipeline-run time and audit time.
- **5 tract-level scored domains** (`scoring/domain_scores.py`): health_burden (CDC PLACES, 16 metrics), access_barriers (PLACES + ACS, 7 metrics), environmental_burden (CalEnviroScreen, 2 metrics), resource_accessibility (1 precomputed straight-line metric), workforce_shortage (2 precomputed metrics). No tract-level ED-utilization domain — HCAI ED data is county-level only with Santa Clara as the sole county present; documented as DEC-023/RISK-015, not silently faked.
- **Two precomputed geospatial metric inputs** (`metrics/precomputed_geospatial.py`): `workforce_shortage_inputs` (HRSA MUA/P via a real direct tract-code join through the source's own `census_tract_raw` field, 46/48 matched — DEC-025; HPSA straight-line proximity restricted to 39 Designated, coordinate-bearing records — DEC-026) and `resource_accessibility_inputs` (nearest clinical-care-site straight-line distance over 178 real HCAI+HRSA candidate sites).
- **Equal-subdomain-weighting aggregation cascade** (docs §6.1) with a 70% coverage threshold producing `NULL` (never zero) below threshold, at every level (metric → subdomain → domain → scenario) — hand-verified in `test_domain_scores.py`/`test_scenario_scores.py`, and re-verified end to end against all 66,504 live `analytics.metric_contributions` rows (`_audit_contributions_sum_to_scenario_score`) and through the live API.
- **7 scenarios + 1 default + 5 sensitivity presets** (`config/scenarios.yml`, `scoring/scenarios.py`): diabetes_prevention, mobile_transit_care, coverage_navigation, older_adult_support, behavioral_health_access, food_access, default_integrated_screen — each a validated weight configuration over the 5 domains. 5th preset renamed `systemic_pressure_first` (DEC-028, no tract-level utilization domain to weight directly).
- **Monte Carlo uncertainty propagation** (`uncertainty/monte_carlo.py`, docs §8.3): 500 draws/scenario, deterministic seed 42, bounded-normal perturbation respecting logical limits (0-100%, ≥0 distances), never perturbing metrics with no real uncertainty field. Reproducibility (same seed → bit-identical output) directly unit-tested and confirmed via persisted seed/n_draws on every `analytics.monte_carlo_results` row.
- **Sensitivity analysis** (`scoring/sensitivity.py`, docs §9): preset sensitivity (5 named weightings) + Dirichlet random-weight sensitivity (1,000 draws/scenario, seed 42, "most influential domain" via one-at-a-time correlation attribution) → 4 canonical stability labels (Robust/Moderately stable/Assumption-sensitive/Data-limited), combining weight-sensitivity with data confidence, never described as intervention-success probability.
- **Data confidence** (`scoring/data_confidence.py`, docs §4.7/§8.4): 4-component weighted score (coverage/precision/geography-quality/freshness), computed per (tract, scenario), never treated as need.
- **Full explainability** (`scoring/explainability.py`, docs §10): every score decomposes to domain/metric contributions with raw value, unit, percentile, weight, uncertainty, source, citation, limitations, plus a stable SHA-256 `scenario_config_hash`. Score-decomposition counterfactual implemented and correctly labeled non-causal.
- **Structured recommendation engine** (`scoring/recommendations.py`): ranked tracts with assumptions, limitations, supporting evidence, and deduplicated source provenance — every claim traceable.
- **Tautology guard** (`validation/tautology_guard.py`, docs §15.1): refuses (not just flags) any correlation whose outcome is a scenario's own component metric, by metric_id or by identical underlying source column. Wired directly into `correlation_diagnostics.py` so a tautological comparison is never computed at all.
- **Correlation diagnostics** (`validation/correlation_diagnostics.py`, docs §15.3): Spearman/Pearson + 2,000-draw bootstrap 95% CI. Used as a convergent-validity check against CDC/ATSDR SVI (`RPL_THEMES`, n=408) for all 7 scenarios — real results, r=0.66-0.81, all non-tautological. A true criterion-validity check against HCAI ED data is not computed (n=1 county, statistically undefined) — reserved for Phase 7 (DEC-033/RISK-015).
- **Location-allocation optimizer** (`optimization/location_allocation.py`, docs §13): OR-Tools CP-SAT maximal-covering-location model, real VTA high-frequency transit-stop candidates (top 50 by ridership), health_burden-weighted demand, optional equity constraint. 3 real solved runs (k=5/2mi OPTIMAL, k=10/2mi OPTIMAL, k=10/1mi correctly INFEASIBLE given the equity constraint) — surfaced transparently, not hidden.
- **Orchestration** (`run_analytics_pipeline.py`): runs the full metric→domain→scenario→uncertainty→sensitivity→explainability→validation→optimization pipeline end to end, loads 13 `analytics.*` warehouse tables (~100,000+ rows total). Wired into `make data` after the Phase 3 core-sources pipeline.
- **Phase 4 audit suite** (`audits/analytics_audits.py`): score-bounds checks (0-100, 0-1 for confidence/probabilities), coverage-suppression-never-silently-zero checks, uncertainty-field-presence checks (PLACES CI, ACS MOE), provenance-completeness checks, tautology-guard enforcement, scenario/registry consistency, the contribution-sum identity (live, against all 66,504 rows), Monte Carlo reproducibility metadata.
